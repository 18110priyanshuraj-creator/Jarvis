# Phase 9 — Autonomous Task Planner

## Goal

Turn a high-level user goal into a structured, ordered, reviewable workflow draft. This phase plans; it does not run workflows or silently create tasks.

## Planning flow

- The authenticated dashboard's **Workflows** area now includes a goal and optional constraints form.
- Recognized study, research/project, writing and organization/build goals are decomposed by deterministic local templates first.
- For unsupported goals, the planner may use the optional AI model configured on the server when planner access is enabled. The browser cannot choose a provider, model, URL, API key or tool.
- If no optional planner is configured and local templates cannot safely understand the goal, JARVIS asks a clarification question rather than inventing steps.
- The model receives the goal and constraints as untrusted data. It cannot call tools or execute actions.

## Plan contract

The planner returns a bounded plan with an objective, constraints, assumptions, optional clarifying questions, ordered steps, validation results, source and explicit approval metadata.

Only these workflow step types may be generated by the planner:

- `create_task`
- `search_knowledge`
- `draft_text`
- `review_checkpoint`
- Read-only summaries: GitHub repositories, Google Drive file list, Telegram bot profile and ElevenLabs account summary

The planner cannot generate memory writes, shell/code execution, messages, publishing, purchases, payments, transfers, deletions, security-setting changes or arbitrary device actions. Plans are limited to ten steps. Longer plans must include a review checkpoint.

## Approval and execution boundaries

- Creating a plan is read-only. It does not store the plan, create a task, call an integration or run an action.
- The **Save as workflow draft** button explicitly saves the proposed steps into the existing Workflow editor as a draft.
- The existing workflow process remains mandatory: validate the saved draft, approve the validated version, then press Run separately.
- Existing review checkpoints still pause workflow execution. Phase 10 remains responsible for execution persistence/recovery improvements.

## Privacy and safety

- Goal length is bounded to 1,000 characters; up to five constraints of 200 characters each are allowed.
- Credential, contact and selected sensitive personal-data patterns are rejected. The pattern checks are safeguards, not a guarantee that every sensitive detail can be detected.
- Harmful, dangerous and exploitative goals are blocked from planning.
- Recognized goals use local rules. Unsupported goals may be sent to the server-configured AI provider only when enabled; the UI discloses this before planning.
- Planner responses are rendered with text nodes, not HTML injection. Plan responses are marked no-store and the endpoint is authenticated and rate-limited.

## API

- `POST /api/planner/plan` — authenticated goal-to-plan proposal; no persistence or execution.
- `POST /api/workflows` — existing endpoint saves a chosen plan as an unapproved workflow draft.
